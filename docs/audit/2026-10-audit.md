# OpenCoop repo audit — 2026-10-25

Point-in-time review of `main` at `8cb8849`. Analysis only. Facts are tied to `path:line`. Judgments are marked as such.

Calibrated to a one-person commercial SaaS: finish and monetise. No rewrite, no new infrastructure.

## Executive summary

**Grade: B-.** OpenCoop is a real multi-tenant product with a clean client/API/DB split, a large automated test suite, and deploys that wait for lint, unit tests, and Playwright. The gaps that matter are narrow: cooperative mail secrets are stored and returned in plaintext, Stripe subscription state is untested and fail-open, and CI never typechecks. None of that calls for a new architecture.

**Top 3 risks.** (1) A settings update returns the coop SMTP password and Microsoft Graph client secret, and both sit unencrypted in Postgres (`apps/api/src/modules/coops/coops.service.ts:534-578`, `packages/database/prisma/schema.prisma:175-186`). (2) Stripe `customer.subscription.updated` stores any unmapped status as `ACTIVE`, and there is no test of the webhook or of failed/expired states (`apps/api/src/modules/billing/billing.service.ts:247-261`). (3) Access and refresh tokens live in `localStorage`, and a stolen refresh token stays valid for 30 days because refresh does not rotate it (`apps/web/src/lib/api.ts:23-36`, `apps/api/src/modules/auth/token.service.ts:21-62` and `:121`).

**Top 3 opportunities.** (1) Encrypt mail secrets with the helper Brevo already uses, and stop returning them. (2) Add billing unit tests and treat unknown Stripe statuses as not active, so a paused or expired subscription cannot keep write access. (3) Add `tsc --noEmit` to the job that already gates deploy. The pipeline shape is right; the missing check is small.

## Repo map

**Purpose.** Multi-tenant SaaS for Belgian (and similar) cooperatives: shareholders, share classes, registrations, payments, dividends, meetings and votes, documents, messages, charge cards, volunteers, and a public signup page. Fact: `README.md:1-3`.

**Users.** Cooperative admins (day to day), shareholders (portal), anonymous visitors (public registration and gift claim), and a system admin. External partners call `/external` with a coop API key. Judgment: one product company, OpenCoop, selling this to cooperatives; billing plans are `FREE`, `ESSENTIALS`, `PROFESSIONAL` (`packages/database/prisma/schema.prisma:77-81`).

**Maturity.** In production. Acc deploys from `main`, prod from a `v*` tag (`README.md:72-76`, `docs/OPERATIONS.md:13-17`). Prisma history runs from `20260222000000_init` through October 2026 migrations. Judgment: past MVP, still one operator (`docs/OPERATIONS.md:19` names a single SSH user).

**Stack.** pnpm + Turbo. NestJS 10 API, Prisma 6, PostgreSQL 16, Redis, Bull. Next.js 15 web (React 18, Tailwind, next-intl). Fumadocs. Stripe Billing. Sentry SDK. Fact from `package.json`, `apps/api/package.json`, `apps/web/package.json`, `deploy/docker-compose.yml`.

**Entry points.** API bootstrap `apps/api/src/main.ts` (Helmet, CORS locked to `FRONTEND_URL`, validation pipe, Swagger off when `NODE_ENV=production`, `:27-58`). Side effects (email, Ponto sync, audience sync) go through Bull on Redis. Stripe and Ponto call public webhook routes. The browser never opens a database connection.

## Audit report

### Strengths

- Auth is layered: 15-minute access JWT, hashed refresh tokens, MFA-pending tokens rejected by the JWT strategy (`apps/api/src/modules/auth/strategies/jwt.strategy.ts:16-19`), TOTP secret encrypted, passkeys, Google/Apple optional. Login and refresh routes are throttled (`apps/api/src/modules/auth/auth.controller.ts:62-92`).
- National register numbers are encrypted with AES-256-GCM (`apps/api/src/common/crypto/field-encryption.ts:15-24`). Brevo API keys are encrypted on write and stripped from the settings response (`coops.service.ts:538`, `:573-576`). Audit logs mask those fields (`apps/api/src/modules/audit/audit.service.ts:6-13`).
- Coop admin routes use JWT + role + coop membership + permission + subscription guards (for example `apps/api/src/modules/admin/admin.controller.ts:83`). Shareholder self-service checks `canActForShareholder` (`shareholder-actions.controller.ts:151-165`).
- Message HTML is allowlist-sanitised, with tests (`apps/api/src/modules/messages/message-body.ts:7-28`).
- Deploy is guarded: immutable SHA tags, migrate before API, health check, no `docker compose down` warning in the runbook (`docs/OPERATIONS.md:133-158`). Postgres and Redis are not republished on each app deploy.
- Domain tests are broad: dividends, registrations, bank import, charge cards, meetings/votes, OGM, volunteers, MCP tools. Playwright covers login, registration, and the shareholder and admin portals.
- Global validation pipe whitelists and rejects unknown fields (`main.ts:37-45`). CORS is a single origin, not `*` (`main.ts:31-34`). Helmet is on (`main.ts:28`).

### Architecture — mostly healthy

Nest modules match the product domains. Web does not import Prisma. Shared pure logic sits in `packages/shared`.

**F1. Medium. Read-only billing is not enforced on the public register or on member capital actions.** `SubscriptionGuard` only blocks non-GET requests when `request.params.coopId` is set; otherwise it allows the call (`apps/api/src/common/guards/subscription.guard.ts:22-37`). Public registration is `POST /coops/:slug/register` with no subscription check (`apps/api/src/modules/coops/coops.controller.ts:62-72`, `coops.service.ts:869-979`). The channel register is the same (`apps/api/src/modules/channels/channels.controller.ts:26-36`). Member buy and sell use `JwtAuthGuard` only (`shareholder-actions.controller.ts:139-141`, `:168`, `:446`). Admin writes are blocked, so an unpaid coop cannot approve from the dashboard, but the public form can still create shareholders and `PENDING` / `PENDING_PAYMENT` registrations (`registrations.service.ts:369`). Judgment: this is a monetisation hole, not an auth bypass. Confirm the product intent before changing it (see open questions).

**F2. Low. `computeIsReadOnly` is duplicated and untested.** The profile path uses `apps/api/src/modules/auth/compute-readonly.ts`. The guard uses the private method on `BillingService` (`billing.service.ts:161-178`). They are the same three rules today (FREE never read-only, `ACTIVE` never read-only, an open trial never read-only). A future edit can make the banner and the guard disagree.

**F3. Low. The shareholder admin page is one 1,676-line component.** Fact from `wc -l`. Judgment: painful to change, not incorrect. Do not split it until a change touches it.

### Code quality — healthy enough

TypeScript is on, DTOs use class-validator, and the risky SQL found in this pass uses Prisma tagged templates (`Prisma.sql` / `$queryRaw` in `analytics.service.ts` and `reports.service.ts`), not string-concatenated user input. `noImplicitAny` is off on the API (`apps/api/tsconfig.json:16`). Judgment: not worth a sweep; new code can stay strict where it already is.

Validation uses `enableImplicitConversion: true` (`main.ts:43`). That is a known Nest footgun. No concrete bug was traced to it in this pass, so it is not a finding.

### Security

**F4. High. Coop SMTP passwords and Graph client secrets are stored in plaintext and returned by settings update.** The schema comment says email configuration is “encrypted in production” (`schema.prisma:175`). `brevoApiKey` is (`:192`, `coops.service.ts:538`). `smtpPass` and `graphClientSecret` are not: empty values are dropped, non-empty values are written as given (`coops.service.ts:534-536`), and `update()` returns the full Prisma row after deleting only `brevoApiKey` (`:555-578`). Both admin settings and the system-admin coop update return that object (`admin.controller.ts:116-136`, `system.controller.ts:64-71`). `getSettings` does exclude them (`coops.service.ts:396`). The mailer then uses the columns as plaintext (`email.processor.ts:220-221` and `:253-256`). Audit logging masks the values (`audit.service.ts:10-11`), so the leak is the database and the HTTP response, not the audit table. MCP coop tools already omit these fields (tested in `mcp-coop.tools.spec.ts`). Judgment: a database backup or a settings-admin browser session is enough to take the coop’s mailbox or Azure app. Not an anonymous bug, so not Critical.

**F5. High. Unknown Stripe subscription statuses are stored as `ACTIVE`.** `handleSubscriptionUpdated` maps six statuses and falls back to `ACTIVE` (`billing.service.ts:247-261`). Stripe also sends `paused` and `incomplete_expired`, which are not in the map. `computeIsReadOnly` treats any `ACTIVE` row as paid (`compute-readonly.ts:15`, and the copy at `billing.service.ts:176`). Judgment: a paused or expired subscription can keep the admin UI writable. Combined with F6, this can ship unnoticed.

**F6. High (standard fail, same theme as F5). No automated test of Stripe checkout, webhooks, or failed/expired states.** The handlers exist (`billing-webhook.controller.ts:55-70`, `billing.service.ts:185-278`) and signature verification is real (`billing-webhook.controller.ts:49-53`). Nothing under `apps/api` describes `handleInvoicePaymentFailed`, `handleSubscriptionDeleted`, or `PAST_DUE`. Judgment: the money path for OpenCoop itself is the least tested part of the API.

**F7. Low. The webhook 400 includes the Stripe library’s error message.** `billing-webhook.controller.ts:52` interpolates `(err as Error).message` into the response. That can tell a caller why verification failed. The signature check itself is correct.

**F8. Medium. Sessions are long-lived bearer tokens in `localStorage`, and refresh does not rotate.** Login stores `accessToken` and `refreshToken` in `localStorage` (`apps/web/src/lib/sessions.ts:59-61`). The API client reads them from there (`api.ts:23`, `:86`). Refresh looks up the hash and returns a new 15-minute access token only (`token.service.ts:21-62`). The file comment says the service “rotates refresh tokens” (`token.service.ts:9-11`); the refresh method does not. New refresh tokens last 30 days (`token.service.ts:121`). Message HTML is sanitised, which lowers the XSS odds, but any future script injection inherits a 30-day session. Judgment: worth doing, not a drop-everything bug. Moving to httpOnly cookies is a larger change than rotation.

**F9. Medium. Gift-certificate download authenticates with the wrong storage key.** The rest of the app uses `accessToken` (`api.ts:86`, `sessions.ts:59`). The download button sends `localStorage.getItem('token')` (`apps/web/src/app/[locale]/dashboard/shares/page.tsx:593-597`). That key is never written. The request goes out as `Bearer null` and the JWT guard rejects it. Judgment: the button does not work. The neighbouring certificate download already uses `apiFetch` (`shares/page.tsx:264-274`).

Other security checks that came out clean:

- No tracked live Stripe keys or private keys (see scorecard 6).
- `/external` requires `ApiKeyGuard` (`external-api.controller.ts:13`). MCP requires a bearer API key (`mcp-auth.middleware.ts:14-22`).
- Uploads of logos and signatures are public by filename (`uploads.controller.ts:12-33`) with `path.basename` against traversal. Logos are `${channel.id}.webp` (`coops.service.ts:633-641`). Judgment: acceptable for images that are meant to appear on public pages. Not a finding.
- Ponto webhook verifies a signature before acting (`ponto.controller.ts:75-105`).
- `pnpm audit` was not executed in this pass (dependencies were not installed). CI runs `pnpm audit --prod || true` (`.github/workflows/build-deploy.yml:46-47`), so a known CVE does not fail the build. Dependabot covers Docker images only (`.github/dependabot.yml`), not npm. **F10. Medium.** The advisory set is unknown from this review.

`deploy/docker-compose.yml:116` sets `NEXTAUTH_SECRET` to `JWT_SECRET`. The web app does not use NextAuth (`README.md:7`, `.env.example:90-93`). Judgment: unused coupling. Left alone because changing the prod compose is out of scope and the web code does not read it for auth.

### Testing — strong, with one hole

API and web unit tests run in CI. Playwright runs against Postgres 16 and Redis 7 with a seed. Auth login is covered (scorecard 4). Share payments, dividends, bank matching, and charge cards have unit tests.

The hole is Stripe billing (F6) and the lack of a typecheck (scorecard 2). E2E also does not apply migration SQL (scorecard 7, **F11** below).

**F11. Medium. CI builds the test database with `prisma db push`, not `prisma migrate deploy`.** `.github/workflows/build-deploy.yml:98-101`. A bad migration can be green in CI and fail only on acc, where the migrate container blocks the new API (so it fails safe) but still needs a manual recovery (`docs/OPERATIONS.md:160-163`).

### Performance — healthy for this size

Hot paths have indexes: registrations, payments, bank transactions, audit log, meetings (`schema.prisma` `@@index` entries, plus migration `20260610120000_add_perf_indexes`). Bull jobs set `removeOnComplete: true` and cap failed jobs at 500 (`app.module.ts:64-68`). A daily cron deletes expired tokens and email logs older than 180 days (`apps/api/src/modules/system/retention.service.ts:6-53`). Audit logs and business rows are kept on purpose (`retention.service.ts:11-13`). Judgment: right call for a register of record. Do not add a retention job for `AuditLog`.

**F12. Low. `/health` opens a new Redis connection on every check.** `health.controller.ts:21-28`. Docker hits this every 10 seconds (`deploy/docker-compose.yml:96-100`) and the deploy script polls it. It works. It does not need a new metrics stack.

No N+1 was measured under load. This audit did not run the app.

### Dependencies — acceptable, audit is toothless

Versions in use are current enough for a small SaaS (Nest 10, Prisma 6, Next 15.5, Postgres 16.15, Redis 7.4). See F10 for the audit gate. No Critical CVE was confirmed, because `pnpm audit` was not run here.

### DevEx / ops — healthy, docs lag the code

Local setup is a short README. Acc and prod are automated. Logs rotate at 10 MB × 3 (`deploy/docker-compose.yml:102-106`). There is no log aggregator and no uptime monitor in the repo; `docs/OPERATIONS.md:193-195` says the uptime monitor still needs to be pointed at `/api/health`. Judgment: fine until a second person is on call. Do not add Loki/Grafana for one box.

**F13. Medium (docs). The debt register and two public sentences contradict the code.** See scorecard 9. `README.md:9` (Next.js 14 vs 15) is the one a new dev will trust first.

Error reporting itself is in good shape for API and web (scorecard 5). `Sentry.captureException` is used on email, auth, Ponto, and schedulers, and the global filter is installed. `docs/OPERATIONS.md:196-197` is the stale sentence, not the code.

### What is not a finding

- Public coop pages returning the IBAN. Shareholders need it to pay. `getPublicInfo` selects bank fields on purpose (`coops.service.ts:143-145`).
- `coop.active === false` meaning “pending activation” in the dashboard banner (`dashboard/layout.tsx:471-476`), not a kill switch. Whether the public form should refuse inactive coops is a product question, not a bug this pass could prove.
- Historical migrations that drop `shares` and `transactions`. They are already the history. Do not rewrite them.

## Strategy

### 1. Mail secrets match the Brevo pattern

**Target.** `smtpPass` and `graphClientSecret` are encrypted at rest, never returned by `PUT` settings, and decrypted only in the mailer. Existing plaintext rows keep working until the next save.

**Won’t fix.** A batch SQL rewrite of every row. The migrate container only has `DATABASE_URL` (`deploy/docker-compose.yml:35-36`), so it cannot see `FIELD_ENCRYPTION_KEY`. Lazy encrypt-on-write is enough.

**Done when.** A settings update response has neither field; a unit test shows the value persisted with an encryption prefix; the mailer test shows a prefixed value is decrypted and a legacy plaintext value is still sent.

### 2. Stripe state is tested and fail-closed

**Target.** Payment failed, subscription deleted, and subscription updated (including `paused`, `incomplete_expired`, and an unknown status) have unit tests. An unknown status is not stored as `ACTIVE`. Webhook failures do not echo the library error. `BillingService` uses the shared `computeIsReadOnly`, and that function has tests for trial, FREE, ACTIVE, and PAST_DUE.

**Won’t fix.** A new subscription-status enum value and a migration, unless a status truly cannot be represented. `PAST_DUE`, `UNPAID`, `INCOMPLETE`, and `CANCELED` already cover fail-closed.

**Done when.** `pnpm --filter @opencoop/api test` covers those cases, and a `paused` event leaves the row not `ACTIVE`.

### 3. CI typechecks the code it already builds

**Target.** The `test` job runs `tsc --noEmit` for the API and the web app (after `prisma generate` and the workspace build it already does).

**Won’t fix.** Turning on `noImplicitAny` across the API. That is a sweep, not a gate.

**Done when.** A pushed PR runs the typecheck step, and a type error fails the job.

### 4. Sessions stop being a 30-day bearer in the browser

**Target (later, not this round of code).** Refresh rotates and revokes the presented token. A follow-on change moves tokens to httpOnly cookies.

**Won’t fix now.** The cookie migration in the same change as rotation. It touches every client call and login method (password, magic link, OAuth, passkeys).

**Done when.** Reusing an old refresh token fails, and a unit test says so. Cookie storage is a separate done signal: no `localStorage` access token on the dashboard.

### 5. Docs describe this tree

**Target.** README names Next.js 15. `TECHNICAL_DEBT.md` either gets a short “superseded” note or loses the claims that are now false. OPERATIONS no longer says web Sentry is future work.

**Won’t fix.** Rewriting the debt register into a new process. One correction is enough.

**Done when.** A new dev following the README does not install the wrong Next major in their head, and the debt file does not claim there are zero unit tests.

### Explicit won’t-fix

| Item | Why |
|------|-----|
| Framework rewrite, microservices, feature-flag SaaS | The module split and `LAUNCH_MODE` are enough. |
| Loki/Grafana or a second error tracker | Sentry SDK + Docker log rotation is the right size. Uptime ping is an external config, not a repo change. |
| Audit-log retention | It is the register of who changed shareholder data (`retention.service.ts:11-13`). |
| Splitting `NEXTAUTH_SECRET` from `JWT_SECRET` in prod compose | Web does not use NextAuth. Editing prod env wiring is out of scope. |
| Rewriting applied destructive migrations | They already ran. New migrations stay guarded by the migrate container. |
| Mobile UIScene / TestFlight items | There is no mobile app. |
| Product analytics as a blocker | Useful later (Plausible or similar). Not ahead of secrets and billing tests. |
